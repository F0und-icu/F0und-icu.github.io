Vulnerability research

Device noted during the original research: a hotel switch at 192.168.48.73. The default credentials admin:admin worked; the password was then changed to 123456. Internal network: Tracing login and related requests led to the following key files: sbin/web The backend uses Lua. The issue appeared applicable across the B0701 software examined here.

httpd lua vulnbility 11

Searching the relevant functions identified eleven command injection locations:

auth analysis

These issues require authentication. To assess whether that boundary could be bypassed, I followed string references to the httpd binary. The login request led to the auth string. The Lua authentication flow is:
LUA
web/routers/init.lua -> web/lib/page.lua
-- Pre-action handler: authentication, session setup, and related operations.
function M.beforeAction(self, controller)
    if (self.auth) then
        --[[session.open()+

         if(not sessData.username) then
              return false
         end]]
        -- unauthenticate.unauthenticate.lua can be accessed without login.
        if(controller == "unauthenticate.unauthenticate") then
            return true;
        end
        M.currentUser = cgilua.servervariable("WEBMASTER_USER") or "";
        if (M.currentUser == "") then
            return 1;
        end
        local list = Utils.StringUtil.split(controller, "%.");
        local id = list[table.maxn(list)];
        local permission_user = permission_id[M.currentUser];
        if (M.currentUser ~= "admin" and (permission_onlyAdmin[id] or not permission_user)) then -- No administrator privileges, or no configured page access.
            return 2;
        end
        if (not permission_map[id] or permission_user=="all" or  M.currentUser == "admin") then
            return true
        end
        if (type(permission_map[id])=="string" and permission_user[permission_map[id]]) then
            return true

        end
    end
    return true;
