Introduction

Research objective: investigate an unauthenticated RCE path reportedly exploited in the wild, with memory corruption as the suspected vulnerability class.

Reconnaissance

Firmware information: The firmware contains two filesystems and targets little-endian ARM.

Extraction on macOS was incomplete in this experiment.

The second filesystem was not relevant to this investigation. The 2020 firmware: Checking binary protections: The protection settings suggested that a buffer overflow could be worth investigating.

Firmware analysis

With the initial information collected, the HTTP daemon became a candidate for an unauthenticated overflow. The firmware includes an SQLite database, and Lua implements much of the application logic. The HTTP middleware is: lighttpd/1.4.55 Emulation attempts were unsuccessful in this environment. At this stage, UPnP was another suspected location for the overflow. got a mistake: The login flow:
LUA
db.lua
-- Checks if row in table with given keyname and value exists.
-- Returns _ROWID_ if exists, false if not or error. 
function db.existsRow (tablename, keyname, keyvalue)
	-- query
    local cur = db.execute(string.format([[
		SELECT *, ROWID AS _ROWID_ FROM %s
		WHERE %s = '%s'
	]], tablename, keyname, keyvalue))

	-- check for rows
	local result = false
	if (cur) then
		local row = cur:fetch ({}, "a")
		cur:close()
		if (row ~= nil) then
			result = row["_ROWID_"]
		end
	end
	return result
end

--Execute the given query and return the resulting cursor and error message.

	cur, errorStr = _DB_con:execute(query)

	if (statusMessage == "" and errorStr ~= "") then

Authentication first checks whether the user exists, retrieves the stored password, and compares a hash against the supplied password.

This appeared susceptible to SQL injection, but only a single statement could be executed; stacked statements were not supported.

After a successful login, loginlib generates a 32-character random cookie value. The database is checked for an existing cookie for that user: an existing record is updated, otherwise a new record is inserted. Cookie validation follows this path: This function validates access to some pages: The cookie string is escaped here, so this path did not provide the same injection opportunity.
The action field can dispatch to Lua files.
The command string must be shorter than 0xf characters.
